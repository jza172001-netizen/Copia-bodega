## Descripción

Cuatro reportes del usuario probando **en la bodega, con nombres reales**, que resultaron tener **una sola raíz**.

## El problema

Creó "Lechada gris claro" y después "Lechada veige", y la app no le avisó que ya existía algo parecido, ni se las agrupó, ni lo dejó ver el histórico junto. Lo mismo en EPP.

Medido con sus nombres:

```
"Lechada veige"      vs "Lechada gris claro"   puntaje   0   NO avisaba
"Guantes rojos"      vs "Guantes negros"       puntaje   0   NO avisaba
"Gafas de seguridad" vs "Gafas"                puntaje 900   sí avisaba
```

`getGenus` solo quitaba **lo que va entre paréntesis**, así que la app únicamente entendía la convención `Guantes (Negro · Nn)`. El bodeguero escribe como se habla en la bodega — "Lechada gris claro" — y ahí la familia no se detectaba. Con "Gafas" funcionaba **de casualidad**: es exactamente el comienzo de "Gafas de seguridad".

## El cambio

`familiaDe(nombre)` = **la primera palabra**, sin el paréntesis.

Primero se probó recortando una lista de colores y calificativos (gris, veige, negro, claro…). Funcionaba para las lechadas, pero dejaba **"Gafas" y "Gafas de seguridad" separadas** — y el usuario corrigió el rumbo: *"cuando abra la familia ya me salen agrupados dentro de gafas todos los tipos, ese es el fin"*. La primera palabra es más simple y más predecible: el bodeguero sabe de antemano dónde va a caer cada cosa. Si esa palabra es muy corta para identificar algo (una inicial suelta, como en su ítem "G plac polvo"), se toman dos.

Con eso, sin tocar las vistas:

- **`clusterGenera`** agrupa por familia → Inventario e Historial juntan las tres lechadas, los tres guantes y las dos gafas.
- **El aviso de parecidos** suma "misma familia" como criterio, además del puntaje de texto. Es lo que fallaba justo en consumibles y EPP.

Y los otros tres reportes, todos en `MovementsView`:

- **El nombre del ítem abre su histórico** — `ItemHistoryModal` ya existía pero solo se alcanzaba desde Inventario.
- **El trabajador va resaltado** y el ítem debajo. Probando en la bodega lo que se busca es de **quién** es cada cosa, no cómo se llama el ítem.
- **"Devolver" abre el formulario** en vez de devolver directo. Antes se saltaba el estado y la revisión de accesorios que se acababa de construir en #38.

## Verificación

`npm run lint` y `npm run build` pasan.

Agrupación, con los nombres reales:
```
  Gafas:   2 → Gafas | Gafas de seguridad
  Guantes: 3 → Guantes negros | Guantes rojos | Guantes (Negro · Nn)
  Lechada: 3 → Lechada gris claro | Lechada veige | Lechada blanca
```

En el navegador a 390px:
```
  OK  el trabajador aparece en el Historial
  OK  el nombre del trabajador va RESALTADO
  OK  el nombre del ítem es tocable
  OK  abre el histórico del ítem
  OK  "Devolver" abre el formulario, no devuelve directo
  OK  el formulario revisa los accesorios
  OK  Inventario junta las lechadas en UNA familia  ->  "Lechada · 2 especies · 14 en total"
```

**Una honestidad sobre la cobertura:** el diálogo de aviso al crear "Lechada blanca" no lo alcancé a ejercer por la interfaz — la navegación del asistente se me atascó. Queda comprobado **a nivel de lógica**: `familiaDe` devuelve "Lechada" para las tres, y familia igual puntúa 1000 contra un umbral de 600. El diálogo en sí quedó verificado en #34 con el caso de las gafas; lo que cambió acá es el criterio de entrada, no el diálogo.

El aspecto no lo puedo juzgar: el CDN de Tailwind está bloqueado en el entorno de pruebas.
