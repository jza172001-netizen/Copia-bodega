## Descripción

Continuación de #34, que arregló la **creación** (el chatbot ya pregunta el grupo). Esto arregla la **vista**.

## Qué problema resuelve

**Inventario** ya juntaba las variantes de una misma familia — `Guantes (Negro · Nn)` y `Guantes (Rojo · Nn)` salían como un solo *"Guantes · 2 especies"* desplegable, vía `clusterGenera`. Pero dos familias emparentadas, **"Gafas"** y **"Gafas de seguridad"**, quedaban sueltas y revueltas con todo lo demás. Faltaba el nivel de arriba.

**Historial**, en su modo *"Por herramienta"*, agrupaba por **ítem exacto**: los guantes negros y los rojos salían en dos bloques separados, y no se le podía seguir el rastro a los guantes.

## Cambios

**`components/InventoryView.tsx`** — las familias ahora van bajo el encabezado de su grupo. `filasAgrupadas` devuelve una sola lista con encabezados intercalados, para no reescribir el renderizado de cada familia.

**`components/MovementsView.tsx`** — el modo "Por herramienta" agrupa por **familia**, ordenado por grupo, con el encabezado apareciendo cada vez que el grupo cambia.

Dos decisiones:

- **"General" queda de último.** Es el cajón de lo que todavía no tiene grupo asignado — y ahora mismo son casi todos los ítems del usuario, creados antes del cambio anterior. No tiene por qué encabezar la lista.
- **Con un solo grupo el encabezado se omite.** No informa nada y es ruido.

Se reusan `getGenus` y `clusterGenera` de `utils/genus.ts`, que ya resolvían la familia. No se escribió lógica de agrupación nueva.

## Verificación

`npm run lint` y `npm run build` pasan.

En el navegador a 390×900, con cinco ítems repartidos en tres grupos:

```
  OK  Inventario: sale el encabezado "PROTECCIÓN PARA OJOS"
  OK  Inventario: sale el encabezado "PROTECCIÓN PARA MANOS"
  OK  Inventario: "General" queda de último
  OK  Inventario: las dos gafas están bajo el mismo encabezado
  OK  Inventario: los guantes siguen juntos como familia (2 especies)
  OK  Historial: agrupa por FAMILIA, no por variante  ->  "Guantes 2 mov."
  OK  Historial: sale el encabezado de grupo
```

La comprobación que más importa es la quinta: que meter el nivel de arriba **no rompiera** el agrupado por familia que ya funcionaba bien.

## Lo que sigue pendiente

Los ítems que el usuario ya tiene creados siguen con `subCategory: 'General'`, porque se crearon antes de #34. Van a aparecer todos juntos bajo ese encabezado hasta que se les asigne grupo — desde Editar ítem, o en una tanda aparte si lo pide. Es una decisión sobre datos reales, no del código.

El aspecto no lo puedo juzgar: el CDN de Tailwind está bloqueado en el entorno de pruebas.
